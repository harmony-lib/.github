## 📖 关于我们

**harmony-lib** 致力于构建**高质量、易用、开源**的通用库集合，专为 **鸿蒙操作系统** 生态打造。

我们相信：一个健康的开源生态，离不开扎实的基础库。无论是网络请求、数据序列化、工具类的封装，还是各类三方库的鸿蒙化移植与优化 —— 我们都在持续努力，让鸿蒙开发像搭积木一样简单。

### 🎯 我们的愿景

- **高质量** —— 每个库都经过完整测试、详尽文档与持续维护
- **易用** —— 开箱即用，与 ArkTS / ArkUI 深度契合，符合鸿蒙开发习惯
- **开源** —— 社区驱动，代码透明，人人可参与、可受益

## 🤝 参与贡献

**我们热烈欢迎每一位开发者参与进来！** 无论是提 Bug、贡献代码、发起讨论，还是分享使用经验，都是对社区宝贵的贡献。

### 🐛 发起 Issue

遇到 Bug 或有功能建议？欢迎通过 Issue 告诉我们。**请按问题归属选择正确的仓库**，以便我们更快定位和处理：

- 📦 **某个具体库的问题**（Bug、功能建议、使用疑问）→ 请前往[该库的仓库](https://github.com/orgs/harmony-lib/repositories)提 Issue
- 🏛️ **组织层面的问题**（跨库问题、新库提议、无法确定归属）→ 请前往 [harmony-lib/.github 仓库](https://github.com/harmony-lib/.github/issues) 提 Issue

**提 Issue 小贴士：**

- 🐞 **Bug 报告** —— 请描述复现步骤、期望结果与实际结果，并附上日志/截图（如有）
- ✨ **功能建议** —— 说明你的使用场景与期望的能力
- 🔍 **使用疑问** —— 请先检索已有 Issue，避免重复；简单疑问也可以在 [Discussions Q&A](https://github.com/orgs/harmony-lib/discussions) 发帖，响应更快

> ✅ 提 Issue 前请先搜索是否已有同类 Issue；请尽量使用英文标题并附上中文或英文详细描述。

### 🔄 提交 Pull Request

想直接贡献代码？非常欢迎！

1. **Fork** 目标仓库
2. 创建你的分支：`git checkout -b feature/my-feature`
3. 提交你的修改：`git commit -m 'feat: add some feature'`
4. 推送分支：`git push origin feature/my-feature`
5. 发起 **Pull Request**

> 📋 PR 要求：请遵循 [Conventional Commits](https://www.conventionalcommits.org/zh-hans/) 提交规范，并确保通过 CI 检查（编译 + 测试）。

### 💬 发起 Discussion

有想法想探讨？有经验想分享？

[组织级 Discussions](https://github.com/orgs/harmony-lib/discussions) 是我们的社区广场：

- 💡 **想法探讨** —— 新方向、新架构、库的演进路线
- ❓ **Q&A 问答** —— 使用中的疑问互助
- 📢 **经验分享** —— 鸿蒙开发实践、踩坑总结
- 🗳️ **投票** —— 社区重要决策

> 💬 相比 Issue，Discussion 没有对错之分 —— 任何畅所欲言的讨论都值得鼓励！

### 🌟 其他参与方式

- ⭐ **Star** —— 你收藏的每一个 Star，都是维护者持续更新的动力
- 📣 **推荐** —— 把好用的库分享给身边的鸿蒙开发者
- 🌍 **翻译** —— 帮助我们完善多语言文档

## 🛡️ 质量承诺

所有 harmony-lib 仓库均遵循统一的质量标准：

- ✅ 严格遵循 [鸿蒙 ArkTS 编码规范](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-coding-style-guide)

- ✅ 语义化版本管理（[SemVer](https://semver.org/lang/zh-CN/)）与清晰的 CHANGELOG
