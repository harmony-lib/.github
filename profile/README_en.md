## 📖 About Us

**harmony-lib** is dedicated to building a collection of **high-quality, easy-to-use, open-source** general-purpose libraries for the **HarmonyOS / OpenHarmony** ecosystem.

We believe a healthy open-source ecosystem is built on solid foundational libraries. From networking, data serialization, and utility wrappers, to porting and optimizing third-party libraries for HarmonyOS — we keep working to make HarmonyOS development as simple as building with blocks.

### 🎯 Our Vision

- **High Quality** — every library ships with comprehensive tests, thorough documentation, and ongoing maintenance
- **Easy to Use** — works out of the box, deeply aligned with ArkTS / ArkUI and HarmonyOS development conventions
- **Open Source** — community-driven and transparent; everyone can join in and benefit

## 🤝 Contributing

**Everyone is welcome to join us!** Filing bugs, contributing code, starting discussions, or sharing your experience — every contribution makes a difference.

### 🐛 Opening an Issue

Found a bug or have a feature idea? Let us know via an issue. **Please choose the right repository based on where the problem belongs** so we can locate and handle it faster:

- 📦 **Issues with a specific library** (bugs, feature requests, usage questions) → please open an issue in [that library's repository](https://github.com/orgs/harmony-lib/repositories)
- 🏛️ **Organization-level topics** (cross-repo issues, new library proposals, or anything you can't attribute) → please open an issue in the [harmony-lib/.github repository](https://github.com/harmony-lib/.github/issues)

**Tips for filing issues:**

- 🐞 **Bug reports** — describe the reproduction steps, expected vs. actual behavior, and attach logs/screenshots if available
- ✨ **Feature requests** — explain your use case and the capability you expect
- 🔍 **Usage questions** — search existing issues first to avoid duplicates; for simple questions, posting in [Discussions Q&A](https://github.com/orgs/harmony-lib/discussions) may get a faster response

> ✅ Before opening an issue, please search for existing ones. English titles are preferred, with details in either English or Chinese.

### 🔄 Submitting a Pull Request

Want to contribute code directly? You're more than welcome!

1. **Fork** the target repository
2. Create your branch: `git checkout -b feature/my-feature`
3. Commit your changes: `git commit -m 'feat: add some feature'`
4. Push to the branch: `git push origin feature/my-feature`
5. Open a **Pull Request**

> 📋 PR requirements: please follow the [Conventional Commits](https://www.conventionalcommits.org/) specification and make sure the CI checks (build + tests) pass.

### 💬 Starting a Discussion

Got ideas to explore? Experience to share?

Our [organization-level Discussions](https://github.com/orgs/harmony-lib/discussions) is the community square:

- 💡 **Ideas** — new directions, architectures, and library roadmaps
- ❓ **Q&A** — mutual help on usage questions
- 📢 **Show & Tell** — HarmonyOS development practices and lessons learned
- 🗳️ **Polls** — important community decisions

> 💬 Unlike issues, discussions have no right or wrong answers — every open-ended conversation is encouraged!

### 🌟 Other Ways to Contribute

- ⭐ **Star** — every star you give keeps maintainers motivated
- 📣 **Spread the word** — share useful libraries with fellow HarmonyOS developers around you
- 🌍 **Translate** — help us improve multilingual documentation

## 🛡️ Quality Commitments

All harmony-lib repositories follow the same quality standards:

- ✅ Strictly follow the [HarmonyOS ArkTS coding style guide](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-coding-style-guide)
- ✅ Full unit-test coverage (based on [hypium](https://gitee.com/openharmony-tpc/testfwk_arkxtest))
- ✅ Bilingual documentation (README.md / README_zh.md)
- ✅ Semantic versioning ([SemVer](https://semver.org/)) with a clear CHANGELOG
- ✅ Timely issue responses and release maintenance
